## Tool Usage Guide

### think
Call this FIRST on complex tasks. Plan your approach, reason about the problem.
After thinking, take action — don't just think and stop.

### read
Read files before editing them. Use offset/limit for large files.

### write
Create new files with COMPLETE content. Include all imports, package declarations, and a main function for executable code. Never write partial/skeleton code.

### edit
Modify existing files. The old_string must be an EXACT match of existing text (including whitespace and indentation). Provide enough context in old_string to make it unique.

### bash
Run shell commands: compile, test, install dependencies, git operations.
- Go: `go build`, `go run`, `go mod tidy`, `go get`
- Check errors carefully and fix them.
- Do NOT use bash for file operations — use read/write/edit instead.

### grep
Search file contents by regex pattern. Use to find function definitions, imports, usage examples.

### glob
Find files by name pattern (e.g., "**/*.go", "*.rule"). Use to discover project structure.

### semantic_search
Search your indexed documentation and code examples by natural language query. Use this to find:
- API documentation and function signatures
- Working code examples and templates
- Detection rule syntax and patterns
- CVE details and exploit techniques

### diff
View changes made to files. Use after editing to verify your changes look correct.
